# Волга-IT: автоматизация тестирования на Python

Автотесты для страниц [Practice Automation](https://practice-automation.com/), реализованные на Python 3.12+, Selenium и Pytest с Page Object Model. Каждый тест запускается в отдельной сессии Chrome. В Allure у сценариев есть читаемые названия, ожидаемые результаты и шаги открытия страницы и проверки результата; действия с виджетами также отмечены отдельными шагами; при упавших тестах сохраняются URL и скриншот.

## Что проверяется

### Calendars — `tests/test_calendars.py`

Позитивные сценарии (10):

1. Заголовок страницы.
2. Подпись поля связана с input, показан формат YYYY-MM-DD.
3. Поле открывает date picker.
4. В календаре показаны месяц, год и кнопки навигации.
5. Следующий и предыдущий месяцы корректно переключаются.
6. Можно выбрать дату следующего месяца.
7. Можно выбрать дату того же месяца следующего года.
8. Можно выбрать следующий високосный день.
9. Правильный ввод соответствует формату виджета.
10. Корректная дата отправляется, и форма показывает подтверждение.

Негативные сценарии (4):

1. Произвольный текст вызывает inline-ошибку даты.
2. Несуществующий день месяца отклоняется с inline-ошибкой.
3. Неверный формат/разделитель отклоняется с inline-ошибкой.
4. После исправления неверной даты inline-ошибка сбрасывается.

Поле календаря — необязательный текстовый input. Проверка формата запускается при потере фокуса; тесты проверяют видимую клиентскую обратную связь, не серверную отправку.

### Modals — `tests/test_modals.py`

Позитивные сценарии (9):

1. Страница открывается с заголовком Modals.
2. Кнопка Simple Modal доступна.
3. Кнопка Form Modal доступна.
4. После открытия Simple Modal видны ожидаемые заголовок и текст.
5. В простой модалке видима и активна кнопка закрытия.
6. Нажатие на закрытие скрывает простую модалку.
7. В Form Modal видны имя, почта, сообщение и кнопка отправки.
8. Имя помечено обязательным в HTML и ARIA.
9. После ввода имени, корректной почты и сообщения отправка показывает подтверждение.

Негативные сценарии (3):

1. Отправка без имени показывает сообщение об обязательном поле.
2. Отправка с адресом `not-an-email` показывает ошибку адреса без подтверждения отправки.
3. Закрытие формы без отправки не показывает подтверждение.

### Ads — `tests/test_ads.py`

Позитивные сценарии (8):

1. Страница открывается с заголовком Ads.
2. Страница сообщает о задержке показа рекламы.
3. Реклама появляется спустя 4–12 секунд после навигации.
4. В рекламе видны заголовок и текст.
5. Кнопка закрытия видима, активна и имеет доступное имя.
6. Нажатие на кнопку скрывает рекламу.
7. Диалог имеет роль и связан с доступным заголовком.
8. После закрытия рекламы сохраняются исходный URL и заголовок страницы.

Негативные сценарии (3):

1. Реклама не активируется раньше четырёх секунд.
2. Щелчок по содержимому не закрывает рекламу.
3. Escape не закрывает рекламу при отключённой обработке этой клавиши.

Время активации фиксируется MutationObserver, установленным до выполнения скриптов страницы. Это позволяет измерять задержку от навигации, а не от момента, когда Selenium уже закончил ждать загрузку.

### Form Fields — требование Automation Tools

`tests/test_form_fields.py` считывает через Selenium пункты списка сразу под подписью Automation Tools, сверяет полный список из пяти инструментов, соединяет их запятыми и вводит строку в Message. Дополнительные проверки покрывают обязательное имя, тип password, флажки, группу радиокнопок и варианты select. Негативный сценарий нажимает Submit с пустым обязательным именем и проверяет, что отправка заблокирована. У поля Email здесь тип `text`, поэтому проверка встроенной браузерной валидации адреса была бы некорректной. Успешную отправку этой формы не выполняем: отдельное требование задания касается заполнения Message, а сайт показывает JavaScript-подтверждение.

## Установка и запуск

Нужны Python 3.12+, Chrome и доступ в интернет при первом запуске: Selenium Manager загрузит совместимый драйвер. Если репозиторий ещё не скачан, откройте командную строку Windows (`cmd`) и выполните:

```bat
cd /d "%USERPROFILE%"
git clone https://github.com/Vova200804/volga-it-python-ui-tests.git
cd volga-it-python-ui-tests
```

Если папка проекта уже есть в домашней папке, откройте `cmd` и обновите локальную копию:

```bat
cd /d "%USERPROFILE%\volga-it-python-ui-tests"
git pull
```

Из папки проекта запустите отдельный набор с видимым окном Chrome или все тесты в фоновом режиме:

```bat
run-tests.cmd -Marker modals -Headed
run-tests.cmd
```

Для других страниц используйте `-Marker calendars`, `-Marker ads` или `-Marker form_fields`. Полный запуск с `-Headed` открывает отдельное окно Chrome для каждого из 45 тестов и на медленном компьютере может занять значительно больше времени. Обычный полный запуск работает в фоновом режиме. В конце выводятся самые долгие этапы тестов: `setup` — запуск браузера, `call` — действия и проверки, `teardown` — закрытие браузера.

`run-tests.cmd` разрешает выполнение PowerShell-скрипта только для этого процесса; менять системную политику не требуется. Скрипт находит Python 3.12+ через стандартный каталог Windows, Python Launcher или PATH, создаёт `.venv` при первом запуске, устанавливает зависимости и очищает прошлые результаты Allure. Если установка пакетов прервалась или изменился `requirements.txt`, повторный запуск устанавливает их снова. Первый запуск дополнительно может загрузить ChromeDriver. При следующих запусках используются готовое окружение и кеш драйвера. Если проект находится в другой папке, укажите её в команде `cd`.

GitHub Actions запускает весь набор на Windows с Python 3.12 и Chrome при каждом изменении репозитория. В артефактах запуска доступны исходные результаты `allure-results` и готовый HTML-отчёт `allure-report`.

Для ручной установки укажите конкретный интерпретатор Python 3.12+ (например, `py -3.12 -m venv .venv`), установите зависимости из `requirements.txt` и запускайте Pytest с `--clean-alluredir`. Чтобы использовать заданный Chrome/драйвер, задайте переменные `CHROME_BINARY` и `CHROMEDRIVER`.

## Allure

После `.\run-tests.cmd` файлы результатов находятся в `allure-results`. Соберите отчёт через `.\make-allure-report.cmd` (нужны Allure CLI или pnpm и Java); HTML появится в `allure-report`. Архив `allure-report.zip` — снимок успешного локального прогона; актуальный отчёт каждого запуска находится в артефактах GitHub Actions. Скриншоты ошибок сохраняются в `artifacts/failures/` и прикладываются к Allure.

## Ограничения

- Внешний сайт может менять DOM, тексты, валидацию и таймер рекламы; текущие локаторы исследованы 23 сентября 2026.
- Проверки Ads зависят от рекламного сценария сайта; при блокировке рекламы тесты покажут таймаут с диагностикой.
- Некорректная почта проверяется по сообщению формы и отсутствию подтверждения отправки; серверный ответ для этого сценария не требуется.
- Список Automation Tools расположен на странице Form Fields; это место и используется для отдельного требования задания.
- В формах не используются реальные персональные данные.
