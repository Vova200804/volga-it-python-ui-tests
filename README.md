# Волга-IT: автоматизация тестирования на Python

Автотесты для страниц [Practice Automation](https://practice-automation.com/), реализованные на Python 3.12+, Selenium и Pytest с Page Object Model. Каждый тест запускается в отдельной сессии Chrome. В Allure у сценариев есть читаемые названия, ожидаемые результаты и шаги; при упавших тестах сохраняются URL и скриншот.

## Что проверяется

### Calendars — `tests/test_calendars.py`

Позитивные сценарии (9):

1. Заголовок страницы.
2. Подпись поля связана с input, показан формат YYYY-MM-DD.
3. Поле открывает date picker.
4. В календаре показаны месяц, год и кнопки навигации.
5. Следующий и предыдущий месяцы корректно переключаются.
6. Можно выбрать дату следующего месяца.
7. Можно выбрать дату того же месяца следующего года.
8. Можно выбрать следующий високосный день.
9. Правильный ввод соответствует формату виджета.

Негативные сценарии (4):

1. Произвольный текст вызывает inline-ошибку даты.
2. Несуществующий день месяца отклоняется с inline-ошибкой.
3. Неверный формат/разделитель отклоняется с inline-ошибкой.
4. После исправления неверной даты inline-ошибка сбрасывается.

Поле календаря — необязательный текстовый input. Проверка формата запускается при потере фокуса; тесты проверяют видимую клиентскую обратную связь, не серверную отправку.

### Modals — `tests/test_modals.py`

Позитивные сценарии (8): заголовок страницы; доступность двух триггеров; заголовок и текст простой модалки; кнопка закрытия простой модалки; наличие полей и submit в form modal; обязательность имени и ARIA-атрибут.

Негативные сценарии (3): сообщение об обязательном имени; отклонение некорректной почты браузерным validity API; закрытие формы до отправки не показывает успешное состояние.

### Ads — `tests/test_ads.py`

Позитивные сценарии (7): заголовок страницы; текст о задержке; появление модалки в заданном интервале; её заголовок и контент; доступная кнопка закрытия; закрытие модалки; корректная связь диалога с заголовком.

Негативные сценарии (3): окно не активируется до порога задержки; щелчок по содержимому не закрывает окно; закрытие не меняет URL и не скрывает заголовок страницы.

Время активации фиксируется MutationObserver, установленным до выполнения скриптов страницы. Это позволяет измерять задержку от навигации, а не от момента, когда Selenium уже закончил ждать загрузку.

### Form Fields — требование Automation Tools

`tests/test_form_fields.py` считывает через Selenium все пункты Automation Tools, соединяет их запятыми и вводит строку в Message. Дополнительные проверки покрывают обязательное имя, тип password, флажки, группу радиокнопок и варианты select. Негативный сценарий нажимает Submit с пустым обязательным именем и проверяет, что отправка заблокирована. У поля Email здесь тип `text`, поэтому проверка встроенной браузерной валидации адреса была бы некорректной. Успешную отправку формы не выполняем: задание требует заполнить Message, а сайт показывает JavaScript-подтверждение.

## Установка и запуск

Нужны Python 3.12+ и Chrome. Selenium Manager получает совместимый драйвер при первом запуске; для загрузки потребуется доступ в интернет. Основной сценарий PowerShell находит установленную версию Python 3.12+ через стандартный каталог Windows, Python Launcher или PATH, создаёт `.venv` при первом запуске и очищает прошлый Allure запуск:

```powershell
./run-tests.ps1
```

Выборочный запуск:

```powershell
./run-tests.ps1 -Marker calendars
./run-tests.ps1 -Marker modals
./run-tests.ps1 -Marker ads
./run-tests.ps1 -Marker form_fields
```

GitHub Actions запускает весь набор на Windows с Python 3.12 и Chrome при каждом изменении репозитория. Результаты Allure сохраняются как артефакт запуска.

Для ручной установки укажите конкретный интерпретатор Python 3.12+ (например, `py -3.12 -m venv .venv`), установите зависимости из `requirements.txt` и запускайте Pytest с `--clean-alluredir`. `./run-tests.ps1 -Headed` запускает Chrome с окном. Чтобы использовать заданный Chrome/драйвер, задайте переменные `CHROME_BINARY` и `CHROMEDRIVER`.

## Allure

После `./run-tests.ps1` файлы результатов находятся в `allure-results`. Соберите отчёт через `./make-allure-report.ps1` (нужны Allure CLI или pnpm и Java); HTML появится в `allure-report`. Архив последнего успешного отчёта включён в проект как `allure-report.zip`. Скриншоты ошибок сохраняются в `artifacts/failures/` и прикладываются к Allure.

## Ограничения

- Внешний сайт может менять DOM, тексты, валидацию и таймер рекламы; текущие локаторы исследованы 23 сентября 2026.
- Проверки Ads зависят от рекламного сценария сайта; при блокировке рекламы тесты покажут таймаут с диагностикой.
- Некорректная почта проверяется встроенным `type=email` validity браузера, не серверным сообщением.
- Список Automation Tools расположен на странице Form Fields; это место и используется для отдельного требования задания.
- В формах не используются реальные персональные данные.
